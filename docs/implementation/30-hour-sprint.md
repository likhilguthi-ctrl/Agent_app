## Immediate blockers and next slice

Do not implement appointments by accepting a client-selected role, tenant, region, identity, or membership. Before the next business workflow, owners must approve: the target-person/membership provisioning interface; canonical region IDs and scope inheritance; reviewer permissions and eligibility; self-approval, expiry, cancellation, and concurrency rules; exact role/region activation semantics; and audit/outbox retention and transaction requirements. These decisions align with architecture sections 10–12 and 19. Once approved, implement the appointment lifecycle as a tenant-scoped, permission-gated module and add positive, denial, cross-tenant, state-transition, concurrency, and audit tests before applying its reviewed migration to any environment.

Local browser authentication is also not accepted: the approved isolated database, existing active membership, verified tenant hostname, and trusted proxy configuration have not been confirmed. See `architecture/phase-4-implementation-status.md` for the local login prerequisites.

## Phase 4.44 — OIDC log safety and activation-intent UI

### OIDC callback logging

- Next.js 14 development request logging uses the Node request URL. The OIDC callback query contains one-use `state` and authorization `code`; the previous direct `next dev` path logged those values.
- `frontend/server.cjs` is now used by both the `dev` and `start` scripts. It captures the callback query in a private in-process header, removes it from `req.url` before Next.js handles/logs the request, overwrites any client-supplied copy of that header, and rejects oversized callback query strings without echoing them. The proxy forwards only the validated callback parameters to FastAPI. State, browser binding, PKCE, and callback validation are unchanged. Invoking `next dev` or `next start` directly bypasses this mitigation.
- `frontend/test/proxy-integration.test.mjs` runs the custom Next server, verifies state/code reach the mocked FastAPI callback, verifies forged internal headers cannot override them, rejects unsupported/oversized queries and a trailing-slash callback path without upstream forwarding, and asserts callback marker values are absent from captured Next output.
- FastAPI also installs `OIDCCallbackQueryScrubbingMiddleware`, which preserves the query through route dispatch and scrubs the ASGI access-log scope afterward. `configure_logging()` disables `uvicorn.access`; application request-completion logs do not include request URLs. The middleware regression test is included in the backend suite.
- No ingress/reverse-proxy configuration was found in project files and no external proxy was inspected or tested. Operators must ensure any upstream load balancer, ingress, hosting platform, and centralized log collector redact callback query strings and protect logs. This change verifies only application-controlled Next logging.
